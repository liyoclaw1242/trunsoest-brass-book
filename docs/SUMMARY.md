# 原型二 總結（2026-10-09）

## 這一版能做什麼，怎麼啟動

一個能從開始畫面玩到三種結局的俯視原型：Blender 腳本產生的村子（4 棟住宅、6 台廣播器、10 段圍籬、2 推車、4 信物、12 界石、4 個村民）、three.js 畫面、規則引擎（條文、公示、重置、漏洞與補丁）、村民 AI（巡邏、追捕、守規則、邊界停下、誘導、喚醒）、輸贏與統計。

```
npm install          # 已裝好：three、vite、@playwright/test（只在本專案）
npm run dev          # http://localhost:5173/  按「開始」
npm test             # 規則引擎 34 項
node tools/playtest.js            # 整局自動試玩（三條路線），需要 dev server
node tools/check-sprint.js 3      # 「什麼都不做就贏」檢查
```

WASD／方向鍵移動，E 互動（數字鍵選其他動作），N 收合筆記，Tab 設計者視角。細節與網址參數見 `docs/playtest/HOW_TO_RUN.md`。Blender（`/Applications/Blender.app`）只在重做場景時需要：`npm run scene`。

## 八個驗證目標

| # | 目標 | 結果 | 依據 |
|---|---|---|---|
| 1 | 規則能指向一類或單一物件，並改變能否使用／進入／取走／破壞 | **成立** | 引擎測試；M3 畫面：聽完「廣播器不得被破壞」後所有完好廣播器出現金框、破壞選項標「違反第六條」、執行後紅色違規提示（`docs/playtest/m3/05`、`06`）。單一物件：`book_01`。 |
| 2 | 物件被破壞後，依賴它的機制跟著改變 | **成立** | M3：砸掉兩台廣播器後站在旁邊聽不到，新條文沒被認知；範圍內的村民有認知（`m3/03`）。廣播條會顯示「廣播中（你聽不到）：第 N 條 ？？？」。 |
| 3 | 保護物件的條文本身也要公示，對聽到的才生效 | **成立** | M3：客觀受保護（設計者視角青框）與玩家認知（金框）分開；走進範圍聽完才出現金框、才算違規。 |
| 4 | 重置撕掉保護條文後，物件重新可破壞 | **成立（引擎與 M3 腳本）；實玩裡看得到但贏不了** | M3：第二次重置後廣播器不再受保護、選項不再標違規（`m3/11`）。整局裡重置會撕掉憲法，村民因此進得了住宅（final/keepsake 撞到重置仍贏；book/deaf 因此輸）。「撕掉書的保護後搬書」這條路沒贏過（open-questions #10）。 |
| 5 | 玩家一眼看得出完好／受保護／損壞 | **成立（腳本與我看截圖）；真人未驗證** | 每種物件有狀態模型（M1 兩張圖、M2 截圖）、金框只畫玩家認知到且目前做得到的（第 1 輪修：壞掉的不框；第 3 輪修：村民只在會拒絕時框、受邀住宅不框）。 |
| 6 | 「聽不聽這條廣播」是不是真正的抉擇 | **不成立** | 三輪評論員一致：聽到規則對外鄉人只有約束沒有好處；贏局裡聽到的條文沒有影響任何決定；裝聾（站在壞掉的廣播器旁、躲在安靜區）是優勢策略。見 open-questions #7。 |
| 7 | 村民取代怪物後，壓力夠不夠、看不看得懂 | **壓力：成立；看得懂：成立（腳本驗證）；真人未驗證** | 壓力：開局直奔 3/3 被抓、被抓後趁免疫直奔 3/3 被抓（`tools/check-sprint.js`）、躲屋會被重置翻轉。看得懂：頭上標籤「人偶／半同化／已喚醒・追你！／回家中」、「村民 02 在住宅 04 門口停下（第三條擋著他：…）」。評論員第 1 輪指出壓力曾只來自一個人偶，第 1–3 輪改動後 book/deaf 路線都輸在壓力下。 |
| 8 | 誘導村民有沒有實際用處 | **成立** | 唯一穩定通關路線（keepsake）全靠誘導：請人拿信物、信物還主人喚醒、用「邀請」支開追捕者。第 2 輪起書看得見這一招：第 3 次誘導寫下「市民不得替外鄉人跑腿」，認知到的半同化村民拒絕，但已喚醒者與「邀請」是條文留的漏洞（事件紀錄 `final/keepsake/events.txt`）。 |

## 三輪評論員說了什麼、怎麼處理

評論員：`playtest-critic` 這個 session 不認得，照你的決定用 general-purpose（model fable）代替、把代理檔原文當指令、要求不改檔案。它每輪都自己重跑 `npm test` 與試玩腳本，並寫自己的實驗腳本。

**第 1 輪**（材料 `docs/playtest/round-1/`）
1. 高｜裝聾是嚴格優勢、聽規則對玩家沒好處、漏洞／補丁整局沒啟動 → 設計層，open-questions #7。
2. 高｜第一次重置後書不再動筆（備用 5 條＝保留 5 條）→ 改：備用條文加 5 條升級版，共 10 條。
3. 中｜書台住宅只有一台廣播器蓋到 → 改佈局：`speaker_03` 移近、半徑 11。
4. 中｜誘導零成本無限次 → 改：20 秒冷卻。
5. 中｜村民被憲法擋住只顯示「過不去」且洗版 → 改：「在住宅門口停下（第 N 條擋著他）」，同地點只記一次。
6. 中｜重置閃現只列條號 → 改：列全文並標「你沒聽過這條」。
7. 低｜喚醒人數重複計、壞掉的物件也畫金框 → 都改。

**第 2 輪**（`round-2/`）
1. 高｜核心迴圈沒登場（對局一分鐘結束、0 重置）→ 改：書自己動筆 50 秒 → 25 秒（critic 建議 12–15，取 25 讓路線有空間）。
2. 高｜「請他搬書」一次誘導 20 秒通關 → 改：「黃銅書不得被搬動」加進開場憲法。
3. 中偏高｜門洞單向（能誘導、能遞信物、抓不到人）→ 觸及你對抓捕判定的決定，open-questions #9。
4. 中｜搬書途中聽到條文仍繼續搬（違反已定案）→ 改：每幀重查，違反就放下。
5. 中｜拿信物收尾立刻被抓、同一信物派兩人 → 改：任務後先走回家；不重複派。
6. 中｜書看不見誘導 → 改：`induce` 動詞、觸發條文「市民不得替外鄉人跑腿」，漏洞（已喚醒者、邀請）是真的。
7. 低｜結局畫面被標籤蓋住、歸還措辭 → 改。

**第 3 輪**（`round-3/`，改後結果在 `final/`）
1. 高｜站著被抓一次再趁免疫直奔 12 秒必贏（免疫期間村民回家）→ 改：免疫只擋抓捕判定；`check-sprint.js` 6/6 被抓。
2. 中偏高｜搬書觸發 count 1 讓搬書路線必死 → 改 count 2；路線仍沒贏，open-questions #10。
3. 中｜一半漏洞文字指向做不到的事 → 改文字；一條條文文字改成與引擎一致。
4. 中｜誘導選項永遠可用、拒絕訊息 undefined → 改：預先標「會拒絕」、3 秒短冷卻。
5. 中｜金框畫在村民與受邀住宅上 → 改。
6. 中｜「聽不聽」仍非抉擇 → 不改，本總結寫不成立。
7. 低｜做不到的選項佔數字鍵 → 改：排最後。

沒有達成提前結束條件（第 3 輪仍有高嚴重度），三輪上限到了。每一輪的完整處理與改後驗證數字在 `docs/changelog.md`。

## 等你決定的問題（`docs/open-questions.md`）

- **#7 玩家聽到規則能換到什麼**（第 1 輪高、第 3 輪再提）：裝聾是優勢；critic 建議取消「安靜處同化度減 1」或讓人偶修廣播器。這是驗證目標 6 的核心。
- **#4／#8 躲進住宅的壓力**：重置撕掉憲法後才翻轉；critic 建議「放棄後要走回家才再追」或書寫「市民得進入任何住宅以執行抓捕」（會和憲法衝突、觸發裁決）。
- **#9 門洞是不是可抓捕的相鄰**：你的決定 2 的解釋。我建議「門開著時門洞與相鄰室內格可抓」。
- **#10 搬書路線在現在的數值下贏不了**：憲法第五條與第三條總是一起被撕。
- **#3 開場 4 秒聽公告凍結**（已暫定）、**#5 村民全圖知道外鄉人位置**（已暫定）、**#6 接任務的村民不抓人**（已暫定）。
- 交接時的 #1 重置後抓捕令的空檔、#2 視角（先用斜俯視）。

## 我沒驗證到的部分

- **真人手感**：所有畫面驗證都是 Playwright 腳本直接呼叫 `step`／`act`，沒有真人用鍵盤玩過；三輪評論員都提到「不知道套路的真人會不會自然地站著聽規則」。
- **通關路線只剩一條穩定的**：keepsake 4/4；deaf 第 2 輪後 1/5；book 0/6。M6 當時（第 1 輪前）兩條都走得通，是優化回合把它們堵掉的。
- **「書活過來」這個結局只用引擎補寫條文驗過**（M5），實玩裡沒有一局撐到第三次重置。
- **第 1 輪 #1 與第 3 輪 #6 的設計問題沒有在畫面上試過任何解法**。
- **評論員不是 `playtest-critic` 本人**：是 general-purpose 代理拿同一份指令跑的，行為應等價但沒比對過。
- Blender 算的兩張圖只有我自己看過；俯視圖看不到屋內的書。
