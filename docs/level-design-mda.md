# 關卡設計流程（MDA 框架）

把 Hunicke/LeBlanc/Zubek 的 **MDA**（Mechanics / Dynamics / Aesthetics）當成我們做 `/puzzle.html` 關卡的作業流程。

> 為什麼要這套：上一輪我純從**機制端**（加法條、加字塊）＋盯一個**動態代理指標**（密度）盲調，結果「分析器放行、玩起來卻太簡單」。MDA 給的紀律正好擋掉這個錯：**美感不能從機制直接讀，要看動態，最後只能靠試玩驗。工具只能認證到動態層。**

---

## 1. 三層（本作對照）

| 層 | 定義 | 本作是什麼 |
|---|---|---|
| **Mechanics 機制** | 規則、資料、演算法——我們唯一能*直接*動的 | 統一裁決 `forbidden(verb, actor, obj)`（permit 蓋 forbid）；身分（外鄉人/市民＋`即`的遞移閉包）；動詞（離開/進入聖所/推/破壞/砍伐/吃/搬書/兩格/持有）；物件地形（石頭填河成橋、可破圍牆、河/洞穴/火會摧毀＝字塊沉沒、樹、斧、鑰匙門、聖所、追逐者、活書/廣播）；可推字塊（名詞/動詞/情態/即），玩家排字改法 |
| **Dynamics 動態** | 機制在玩家操作下隨時間跑出來的行為 | 借名分（宣告身分借他人的權）、稀缺取捨（單一「即」同時只能是一條法）、順序相依（先架橋後離開、先破牆後離開）、重定義（把障礙讀成工具：石頭＝橋）、不可逆與自困（填錯格/推字入河→soft-lock）、矛盾作廢、時間壓力 |
| **Aesthetics 美感** | 想在玩家心裡激起的情緒 | 見下 §2 |

**兩個方向**：設計者由下往上造（機制→動態→美感）；玩家由上往下感受（美感→動態→機制）。所以**從美感往回推**。

---

## 2. 本作的目標美感（開工前先定這個）

用「8 種樂趣」挑，別用含糊的「好玩」：

- **主：Challenge（挑戰）**——卡住→想通→過關。
- **主：Discovery（發現）**——那一下「原來如此」。Baba 式解謎的命脈。
- 輔：**Narrative（敘事）**——被一本官腔的活法典慢慢收編的寓言。
- 輔：**Expression（表達）**——你自己鑽出來的歪招。
- 明確**不追**：Sensation、Fantasy、Fellowship、Submission。

> 每一關開工，先寫一句話：**「這關要給的那一下是什麼」**。
> 例：狐假虎威＝「發現石頭不是障礙、是橋」＋「單一『即』逼出的順序焦慮」。

---

## 3. 設計迴圈（每關照跑）

```
A 定美感意圖 ──► B 反推動態 ──► C 選機制落地 ──► D 工具驗收(動態層) ──► E 試玩驗收(美感層) ──► F 回修
         ▲                                                                          │
         └──────────────────────────────────────────────────────────────────────────┘
```

- **A 美感意圖**：一句話 + 主樂趣類型 + 預期的關鍵步/aha。
- **B 反推動態**：要跑出那個美感，需要哪些動態特徵？（見 §4 的對照）
- **C 機制落地**：用現有詞表/地形/即把動態做出來。守**無裝飾字**（每個放進關的字都要被某動作判定到，否則別放）。
- **D 工具驗收（只到動態層）**：`node tools/analyze.js <關名>`。**只能證明「結構健全」，不能證明「好玩/夠難」。**（§5 左欄）
- **E 試玩驗收（美感層）**：人實際玩，回報 §5 右欄。
- **F 回修**：**若 D 達標但 E 不達標**（＝上次那個坑），代表機制沒種出該動態——回 B/C，不是去改指標門檻。

---

## 4. 把美感翻成機制手段

設計者不能直接「做出美感」，只能選機制、讓它跑出對的動態。對照表：

| 想要的美感 | 要的動態 | 可用機制手段 |
|---|---|---|
| **Discovery** | 有一個**不被明示**的關鍵步 | 關鍵步去明示（`即`-鏈 `外鄉人即市民、市民即山羊` 遞移借權，取代直接給 `山羊得離開`）；讓最明顯的讀法是錯的；把物件重定義（石頭＝橋）；矛盾/捷徑放深處 |
| **Challenge** | 稀缺、順序、風險、長度 | 單一「即」/單一石頭的稀缺；強制順序；不可逆與 soft-lock 風險（**乙案**：可見＋易撤銷）；拉長解法 |
| **Expression** | 存在多條合法解 | 留複數最短/近最短解類（數得出來） |
| **Narrative** | 法條像一本活法典 | 官腔法條；主題一致（借名分、勞動供養、慢慢收編） |

---

## 5. 驗收：動態（工具能認證）vs 美感（只能試玩）

**關鍵心法：指標過關 ≠ 好玩。** 指標的職責是**擋掉結構壞的關**，不是保證好玩。

| 動態層 · `analyze.js` 能認證 | 美感層 · 只能靠人試玩回報 |
|---|---|
| 可解（sound 真解） | 有沒有一個**不被明示**的關鍵步？（Discovery 的必要條件） |
| **全法 load-bearing**（移除任一→無解或變簡單）→ 擋「裝飾法」 | 走錯的路**誘不誘人**？（誘餌有沒有欺騙性，或一眼就排除） |
| **無假 soft-lock**（必要資源不會被無預警推去摧毀）；真 soft-lock 要「可見＋易撤銷」 | 卡住時是「**想不到**」(好) 還是「知道要幹嘛但**很煩**」(壞，Challenge 淪為 chore)？ |
| **不過淺**：看多軸（解長 / 探索狀態 / 互動法對 / soft-lock 陷阱），非只看密度；`偏淺`旗標 | 解出來後有沒有那一下「**啊**」？ |
| min-steps 已知（給「步數上限/將軍」類用） | 用時：太快＝太淺；久且無進展＝太悶或不公平 |

> 密度（`avgOpts`）只量「規則分支」，**看不見空間/推箱路線與自困風險**——這是它放行狐假虎威的盲點。故動態驗收一律看多軸，別回頭盯單一數字。

## 6. 每關一頁工作單（複製這段）

```
關名 / 章節：
① 目標美感（一句話 + 主樂趣）：
② 預期的「aha」/ 關鍵步：
③ 這關倚重/新增的動態：
④ 落地機制（法條、字塊、地形）：
⑤ 工具驗收 analyze.js：
    可解 __ 巨觀步 / 全法 load-bearing? __ / 互動法對 __ /
    soft-lock（真:__ 偽:__）/ 探索 __ 狀態 / 偏淺? __
⑥ 試玩驗收（人）：
    關鍵步被明示了嗎? __ / 誘餌誘人? __ /
    卡點是想不到還是煩? __ / 有沒有 aha? __ / 用時 __
⑦ 回修紀錄（D 達標但 E 不達標時，改了哪個機制去補哪個動態）：
```

## 7. 已有關卡的 MDA 復盤（示範）

- **舊「狐假虎威」(已汰換)**：動態驗收勉強過（密度 2.33），但美感失敗——兩個節點各自獨立、每個選擇被許可字**明示**＝「辨認」非「推理」，Dynamics 跑不出 **Discovery**。這就是 §3 的 F：D 過、E 不過。
- **「出入之間」**：Discovery 清楚（進得去的身分出不來、出得來的身分進不去，要在聖所內宣告）。動態＝順序相依＋重定義身分。
- **現「狐假虎威」(三層)**：Discovery＝「石頭是橋」；Challenge＝單一「即」的稀缺＋先破牆後離開的順序＋填錯自困。動態多軸都是全關之最、6 法全 load-bearing。**但仍是「辨認＋推理」混合**（許可字仍明示要宣告誰）——下一步若要更強的 Discovery，方向是 §4 的「去明示」（即-鏈借權）。
