# 規則書 · 組合式規則系統（給大地圖用）

目標：用一小套「名詞 × 情態 × 動詞」加上「即（定義）」，讓玩家能在地圖上即時排出、改寫規則，組合出極多種互動——規則與物件一致、可預期、無死字。大地圖「烏托邦」就建在這套系統上。

## 文法

一條法＝相鄰字塊排成一句（橫或直），每回合重算（`parseTiles`）：

- 律法：`主詞 · 情態 · 動詞`，如「外鄉人｜不得｜離開」。
- 定義：`主詞 · 即 · 主詞`，如「外鄉人｜即｜市民」——是前者的，也成為後者（名詞重定義）。

玩家推字塊即改規則；把字塊推下洞穴／推進火／沉入河＝永久刪字。

## 詞表（每個都被引擎判定，無裝飾字）

- **主詞／名詞**：外鄉人、市民、任何人、山羊、生物、物、樹木、圍牆。
- **情態**：不得(forbid)、得(permit)、即(is/定義)。
- **動詞**：離開、進入、推、吃、搬書、砍伐、破壞、持有、兩格。

## 一致的裁決（組合深度的來源）

1. **名詞集**：每個實體「是」哪些名詞——天生（`BASE_NOUNS`：山羊＝山羊/生物/物…）＋「即」定義的遞移閉包（`applyIs`）＋拾取定義（持名牌＝市民）。
2. **統一裁決 `forbidden(verb, 行動者名詞集, 受體)`**：掃所有該動詞的生效法，`who` 比對行動者或受體名詞、`target` 比對受體；**permit 蓋過 forbid**。所有動作（離開／進入／推／吃／砍／破／持有／兩格）都走這一條，沒有特例 → 不易出 bug，且任何你排得出的句子都有可預期的效果。
3. **屬性即規則**：「兩格」等性質也是動詞——「生物不得兩格」減速追逐者、「外鄉人得兩格」讓你一步兩格；因為 who 泛用，可套到任何名詞。

### 為什麼能組出上千種互動

8 名詞 × 2 禁准 × 9 動詞 ≈ 一百多條單句律法，加「即」定義 8×8 條可重寫「什麼是什麼」。真正的組合爆炸在於**情境**：場上哪些句子同時成立、字塊被推到哪、物件與地形如何介入，皆由同一套裁決決定。例：

- 「山羊即市民」→ 管市民的法全部套到山羊身上（連「市民不得離開」都綁得住羊）。
- 「圍牆即生物」＋「生物不得兩格」→ 對牆無意義，但「圍牆得破壞」＋破壞動作＝鑿牆。
- 把「不得」推下洞穴＝刪掉任一條禁令；推進河則沉沒；推進火則燒毀——同一個刪字動作、三種地形。

幾個名詞與動詞自由組合、加上可刪可改的字塊與多種地形，情境數遠超千種。

## 物件與地形（每個都有主動互動）

| 符號 | 物件/地形 | 互動 |
|---|---|---|
| 📛 名牌 / 👕 衣物 | 定義物 | 拾取＝成為市民（`def`）；「聽過廣播者不得領名」可擋 |
| 🪓 斧 | 裝備 | 拾取後可砍樹；「不得持有裝備」會被強行卸下 |
| 🌳 樹 | 障礙 | 持斧砍倒；「樹木不得砍伐」擋手，改寫才砍得動 |
| 🐐 山羊 | 生物/代勞 | 推去吃公告（廢 onNotice 法）、馱書出荒野；「山羊不得吃」「物不得推」各自管牠 |
| 🐺 追逐者 | 生物 | 每回合走 1–2 格撲你；「生物不得兩格」減速 |
| 🪨 石 | 可推 | 推入河→填成橋（沉）；推下洞穴/火→消失 |
| 🧱 圍牆 | 可破邊界 | 撞＝破壞；「圍牆不得破壞」擋，改寫才破得了 |
| 🚧 大門 | 鎖 | 有鑰匙或市民到場才開 |
| 🗝️ 鑰匙 | 物 | 開大門 |
| 🕳️ 洞穴 | 地形 | 推進去的字塊/物件永久消失 |
| 🔥 火 / 木地板 | 地形 | 火沿木蔓延、燒字、燒到你＝輸；推字入火＝燒毀 |
| 🌊 河 | 地形 | 過不去，石可填成橋 |
| 聖所（紫） | 地形 | 「不得進入」把不合格身分擋在界外 |
| 🪧 公告 / 📣 廣播 | 公示 | 讀到/聽到才綁你；公告毀則其上法失效 |

## 大地圖「烏托邦」（`chapter:'village'`）

教學之後的主體驗：一步一回合探索開放村莊，規則散在屋舍/河畔/森林中央/聖所深處。兩條出路共用同一串前置關卡，最後二選一——**每個字、每件物都有用**：

1. 領名→成市民（否則跨不進**聖所**）。
2. 進聖所取**斧**。
3. 改寫**「樹木不得砍伐」**（推「不得」入洞穴）→ 砍開**森林**進內院。
4. 跨河：把**石**推進河造橋才到得了東側。
5. 內院二選一：**甲**抱**鑰匙**去開**大門**；**乙**改寫**「圍牆不得破壞」**、**鑿穿圍牆**而出。

驗證：大地圖動件多、超出 BFS 窮舉上限，故用 `node tools/village-verify.js` 以尋路腳本跑**兩條出路皆通**＋**反例**（不領名取不到斧、不砍樹進不了內院）。小關卡仍由 `node tools/puzzle-verify.js` 窮舉驗證（village 關自動跳過）。

## 關卡結構（2026-10 改版）

只剩兩章，之後都往大地圖設計：

- **教學（`tut`，10 關）**：一關一招，循序接上大地圖機制——名/定義 → 鑰匙·大門 → 改寫字塊 → 投穴消字 → 斧·砍樹 → 鑿圍牆 → 石橋 → 聖所·進入 → 即(下定義) → 矛盾作廢。小關，`tools/puzzle-verify.js` 窮舉驗證。
- **村莊（`village`，大地圖）**：開放探索（見下）。目前一張「烏托邦」，之後持續新增同類大地圖。動件多超出 BFS，用 `tools/village-verify.js` 腳本驗證。

（已移除舊的「負荷／野外／險境／定義」離散小關卡；其機制與刁鑽解法併入教學或留待大地圖使用。「即」的經典用法——借山羊的離開權、借市民的砍伐權、物即山羊推石填河——見教學九與大地圖。）

## 擴充原則

- 新動詞：加進 `VERB`，並在引擎用 `forbidden(verb, …)` 判定（走統一裁決，別再寫特例）。
- 新名詞：加進 `SUBJ` 與 `BASE_NOUNS`。
- 新物件/地形：加進地圖字元表與 `_apply`，互動盡量化約成既有動詞（推/破/進入/沉…）。
- 「無裝飾字」：每個放進關卡的字都要能被某個動作判定到；否則別放。
